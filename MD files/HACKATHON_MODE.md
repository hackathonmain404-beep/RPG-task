# Hackathon Mode

## Goal

Deliver a complete, polished, reliable Life RPG within the hackathon window.

## Priority

### P0 — mandatory
- auth
- persistent database
- task CRUD
- task completion
- non-linear XP
- streak
- attributes
- currency/economy
- inventory/shop
- responsive/accessibility
- production backend
- public GitHub
- live deployment
- 3+ meaningful chronological commits
- 90–180 second video under 100MB
- README + `.env.example`

### P1 — score enhancers
- exceptional visual theme
- sophisticated tactile feedback
- polished character page
- achievement/badge system
- theme/equipment customization
- activity analytics
- strong empty/error states
- excellent landing-page SEO/content
- polished onboarding

### P2 — only after P0/P1
- elaborate animations
- extra social systems
- complex notification systems
- unnecessary AI features
- elaborate multiplayer

## Time checkpoints

- **+1 hour:** Architecture, repo, DB/auth skeleton and frontend shell.
- **+4 hours:** Auth + CRUD working.
- **+8 hours:** Completion + XP + level + persistence working.
- **+12 hours:** Streak + attributes + economy/inventory working.
- **+16 hours:** Polished full user journey.
- **+19 hours:** Security/accessibility/SEO/performance audit.
- **+21 hours:** Production deployment and video.
- **+23 hours:** Freeze major changes.
- **+24 hours:** Submit.

## Freeze rule

After the final freeze:
- no architecture changes
- no new dependencies
- no new major features
- bug fixes only

## Team rule

Do not block the whole team on one difficult feature. Create a stable fallback that remains truthful and continue.

## Judge-first rule

Every remaining hour must answer:
> Does this increase score, reliability or proof of a requirement?
If not, skip it.
